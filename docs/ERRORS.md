# Zenith Gaming Daemon: Error Codes & Diagnostics Directory

> **Document Version**: 1.0.0  
> **Status**: Official Diagnostics Guide  
> **Rule**: Every error message generated by Zenith must reference an explicit error code (`[ZENITH-EXXX]`) and provide actionable remediation steps.

---

## Error Catalog

### `ZENITH-E101`: Socket Connection Failed
- **Description**: `zenithctl` or a client process failed to connect to the Zenith daemon UNIX domain socket (`/run/zenith/zenith.sock`).
- **Possible Causes**:
  - The `zenith.service` systemd daemon is not running.
  - The socket file was deleted or moved.
- **Fix**:
  ```bash
  sudo systemctl start zenith.service
  sudo systemctl status zenith.service
  ```

---

### `ZENITH-E102`: Unauthorized Peer / Permission Denied
- **Description**: The connecting process failed kernel credential authorization (`SO_PEERCRED`). Zenith restricts control commands to `root` and members of the `wheel` or `gamemode` groups.
- **Possible Causes**:
  - The calling user is not in the `wheel` or `gamemode` group.
- **Fix**:
  ```bash
  # Add user to the wheel group:
  sudo usermod -aG wheel $USER
  # Or run with sudo:
  sudo zenithctl <command>
  ```

---

### `ZENITH-E103`: Malformed or Unknown Protocol Command
- **Description**: The daemon received an unrecognized command or an unsupported protocol version.
- **Possible Causes**:
  - Version mismatch between `zenithctl` and `zenith` daemon.
  - Corrupted JSON payload over the control socket.
- **Fix**:
  ```bash
  # Verify versions match:
  zenithctl version
  sudo systemctl restart zenith.service
  ```

---

### `ZENITH-E104`: cgroups v2 Hierarchy Missing or Inaccessible
- **Description**: Zenith failed to locate or configure `/sys/fs/cgroup` controllers (`cpu`, `cpuset`).
- **Possible Causes**:
  - Legacy cgroups v1 is active.
  - Unified cgroup hierarchy is disabled in kernel boot parameters.
- **Fix**:
  Ensure your bootloader (systemd-boot / GRUB) includes:
  ```bash
  # Add to kernel command line:
  systemd.unified_cgroup_hierarchy=1
  ```

---

### `ZENITH-E105`: State Journal Conflict or Lock Contention
- **Description**: Another instance of Zenith is currently active or holds the daemon lock (`/run/zenith/zenith.lock`).
- **Possible Causes**:
  - Running `zenith tune` manually while `zenith.service` is actively managing a game session.
  - Stale lock file after an unclean reboot.
- **Fix**:
  ```bash
  # Inspect active holding process:
  sudo zenith status
  # Emergency rollback if needed:
  sudo zenith --rollback
  ```

---

### `ZENITH-E106`: Safe Mode Active / Crash Loop Detected
- **Description**: Zenith detected $\ge 3$ abnormal terminations within a 10-minute sliding window and engaged Safe Mode, disabling aggressive hardware mutations.
- **Possible Causes**:
  - System instability, GPU driver crash, or kernel panic during game session.
- **Fix**:
  ```bash
  # Inspect crash history:
  cat /run/zenith/crash_history.json
  # Reset safe mode:
  sudo zenithctl reset-safemode
  ```

---

### `ZENITH-E107`: AMD 3D V-Cache Driver Mode Unavailable
- **Description**: Zenith attempted to activate hardware V-Cache driver mode via `/sys/devices/platform/amd_x3d_vcache/amd_x3d_mode`, but the kernel driver is not loaded.
- **Possible Causes**:
  - Running on a kernel prior to Linux 6.13.
  - Processor does not possess asymmetric 3D V-Cache CCDs (e.g. single-CCD 7800X3D or standard Ryzen).
- **Fix**:
  - Zenith will automatically fall back to custom L3 cache pinning. No action required unless running on 7900X3D/7950X3D with kernel 6.13+, where updating the kernel enables the native driver mode.

---

### `ZENITH-E108`: Pressure Stall Information (PSI) Not Supported
- **Description**: `/proc/pressure/{cpu,memory,io}` files were not found. Adaptive controller closed-loop degradation cannot operate.
- **Possible Causes**:
  - Kernel compiled without `CONFIG_PSI=y` or disabled via boot parameter.
- **Fix**:
  Add `psi=1` to kernel command line in your bootloader.
